# SL Tour Finder — 導入と操作

更新日：2026-11-28。現行リポジトリの実装を説明します。公開中のWebアプリへの反映・Google上の実動作とは区別してください。

日常操作はHTML版の[取扱説明書 / User Guide](index.html)を参照してください。日本語・Englishは同じページで切り替えます。ブラウザーの優先言語で自動表示し、上部のセレクターで手動変更もできます。アプリ上部の「取扱説明書」は、所有者が設定したURLを新しいタブで開きます。URLは1つだけ設定します。固定の取説URLはありません。

保存先は[TourDB](https://docs.google.com/spreadsheets/d/1UGHv-DeBq2LEuLolF7hGVXXkZTBBlo1hE25Gy2_3s-M/edit)です。他のスプレッドシートや認証プロジェクトは使用しません。

## 1. 最初の操作

1. 運用担当者から案内された通常のWebアプリURL（末尾 /exec）を開きます。
2. 本人確認画面が出た場合は、保持のON/OFFを選んで「Googleでログイン」を押し、指定グループのGoogleアカウントを選びます。確認中は元のアプリのタブを開いたままにします。
3. 元のタブに候補画面が出たら「Linden検索 → 検索設定」を開きます。初回はSSJ向けの未実施AND公式未掲載、検索語は * です。前回の検索は検索JSONの管理から読み込みます。
4. 必要な条件を指定して「完了」で戻り、「Lindenで検索」を押します。設定を閉じるだけでは検索しません。
5. 候補にチェックし、「選択した候補の取り込みを確認」で対象名・件数・登録済み候補の処理を確認して取り込みます。
6. 「取り込み結果」でDB保存と自動照合の結果を別々に確認します。ツアー後は実施記録と記念写真を保存します。

目的は、JapanHirobaのSupportStaffJapanがKankou Tourでまだ実施しておらず、リンデンのおすすめ・行き先ガイドに未掲載の場所を探すことです。景観・撮影・散策で約1時間を過ごせるか、広さと見どころ・ルートから判断します。面積に固定の下限はありません。Lindenの公開情報取得にSecond Lifeアカウントやログインを要求しません。

検索の保存・復元の警告、復元通知、取得終了・停止は、新しい通知が発生すると自動でポップアップ表示します。編集中の画面・入力は保持します。同じ通知は閉じた後に繰り返さず、新しい取得完了や再発した警告は再び自動表示します。結果操作欄の「通知」ボタンも残し、閉じた後も手動で再確認できます。開いている通知は新しい結果へ更新します。保存に問題がある場合は検索JSONを保存できます。取得中の進捗と停止操作は表示を維持します。列見出しはグリーン・白文字、上の操作エリアはグレーです。

JSON読み込みに成功した場合は以前の復元警告を解除します。自動保存の失敗はDriveへのJSON保存の失敗として区別します。自動保存名はAuto_とUTC日時、手動保存名はJST日時付きです。

## 2. Googleログイン・7日間保持

スタッフの利用許可は、TourDBを編集共有しているssj-sl-data-manager@googlegroups.comへの所属で判定します。個人許可リストへの登録は不要です。担当者一覧への登録や個別編集共有だけでは、スタッフの利用許可になりません。DB所有者の管理権限は維持します。

| 保持の選択 | 動作 |
| --- | --- |
| ON（初回の既定） | 同じブラウザープロファイルで開き直しても、Googleログインから最大7日間、本人確認を再利用する。使用のたびには延長しない |
| OFF | 現在のタブ内だけ保持する（最大6時間）。タブを閉じた後は再確認する |

ON/OFFの選択自体も次回へ保存します。ログアウト・期限切れ・接続設定変更・ブラウザー保存の消去では再確認します。保存を拒否された環境では、タブ内だけの保持になることを画面に表示します。シークレットモード等では閉じると保存が消える場合があります。

Google確認が終わると確認用タブの自動終了を試みます。閉じない場合は「このタブを閉じて戻る」、それでも閉じなければ手動で元のタブを選びます。「アプリを開く」は元のタブを閉じた場合に使います。候補画面が出るまでは元のアプリを閉じないでください。

保持機能は未保存の編集・選択写真を保存する機能ではありません。期限切れの再確認では画面内の入力・選択を保持し、保存を勝手に再送しません。グループ所属と指定グループ共有は操作ごとに再確認します。詳しくは[認証・アクセス手順](access.md)を参照してください。

## 3. 画面と操作の違い

上部のLanguage / 言語ラベルと選択欄の間に、サーバーで確認済みの利用者メールアドレスを表示します。追加のGoogleログインを経由しない場合も表示し、処理実行者や担当者の選択値を流用しません。言語欄の高さは50px内です。長いアドレスはクリックして全文を確認できます。

| 画面・操作 | 用途 |
| --- | --- |
| Linden検索 | 公開Webから新しい候補を取得する |
| 登録済み候補 | DB内の候補を絞り込み、採否・メモ等を編集する |
| 実施履歴 | 実施日・担当者・ツアー名・記念写真を管理する |
| 確認履歴 | 確認結果・日時・根拠・変更前後を確認する |
| 削除済み | 削除した候補を確認・復元する |
| 設定 | 担当者・ツアー名・写真保存先を管理する。Googleログイン設定はDB所有者のみ |

検索結果・登録済み候補の名前やカード／一覧行の余白から「詳細・操作」を開けます。名前ボタンはTabとEnter／Spaceでも操作できます。チェック・リンク・操作ボタンは独立します。詳細を開くだけでは取得・保存をしません。

「メモ(注記・確認根拠など)」はカードと一覧に表示し、詳細で全文を確認できます。登録済み候補と一致するWeb結果にもメモを表示しますが、公開検索JSONには入れません。DBの列名「メモ」は変更しません。

Linden検索は表示対象の取得済み候補を全件表示し、表示件数指定・表示用ページ送りは置きません。他の4データ画面ではカード／一覧・6/12/24/48件・ページ送りを使えます。共通の全画面操作は、Googleのフレーム制限があれば表示可能な領域内で拡張します。言語はブラウザー優先言語から自動選択し、自動／日本語／Englishで変更できます。

| 操作 | 保存・取得するもの |
| --- | --- |
| 上部「リセット読み込み」 | 保存済みDBを読み直す。DB初期化・Linden再検索・未保存編集の保存ではない |
| 「Lindenで検索」 | 指定条件で1ページ目からWeb取得を開始する |
| 「追加取得」 | 保存した取得位置から続きを取得する。完了後も要求できる |
| 検索JSONの保存・読み込み | Linden検索の続きだけを保存・復元する。DB・履歴・写真のバックアップではない |

## 取扱説明書URLを指定する（所有者）

1. 「設定 → 取扱説明書 → 開く」を選びます。
2. HTTPSの取扱説明書URLを1つ入力します。日本語・Englishはリンク先の同じページで切り替えます。
3. 保存して「保存済みのリンク」と保存結果を確認します。ヘッダーのリンクはすぐ切り替わります。

旧設定がある場合は、通常URLだけを使用します。通常URLが空なら未設定とし、旧英語版URLを引き継ぎません。読み込みだけで保存設定を書き換えません。所有者が保存すると単一URL形式へ移行し、旧2項目と新URLを変更履歴へ残します。更新対象はMain.gs・Index.htmlで、反映には既存Webアプリの版更新が必要です。リンクはログイン前の画面とGoogleログイン設定でも使用します。入力したURLのクエリー・フラグメントを保持し、言語や章名を自動追加しません。URLを空欄にして保存すると無効になり、固定の代替サイトへは移動しません。設定はScript PropertiesのTOUR_MANUAL_SETTINGSに保存し、URLの変更前後を確認履歴へ記録します。DB列・スコープ追加・Googleログイン設定JSONの再登録は不要です。

## 4. 検索条件

「検索設定」ポップアップの基本／面積／カテゴリー／取得／保存・再開を使います。登録済みDBの検索には追加条件もあります。「完了」・閉じる・Escapeは指定を保持して戻る操作で、検索語のEnterでも取得しません。メイン画面の検索ボタンで反映します。変更未反映の場合は画面に表示します。

- 初回Linden検索はSSJ未実施AND公式未掲載。登録済みDBの検索とWeb探索は別です。
- 追加条件の「適用しない（全て出る）」は、その項目で絞り込まない意味です。未確認も含みます。
- 成熟カテゴリはGeneral／Moderate／Adultの複数チェックです。選択内はOR、別の条件とはANDです。3つを明示指定した場合は、成熟カテゴリ未確認を含みません。
- 公開取得できない成熟カテゴリは取得不能として案内します。Adultのみの取得はできず、ほかと併用すれば取得できる結果を残します。ログイン要求・制限回避はしません。
- 面積は任意の下限・上限と、対象パーセル／対象パーセル合計／リージョン全体を指定します。未確認の面積を指定値に合うと見なしません。
- カテゴリーはプリセットと独自カテゴリーのチェック式複数選択です。独自名は1件ずつ追加します。カンマ区切り入力は不要です。未適用なら独自・未分類も含みます。新規Web候補のカテゴリーを自動推定しません。
- 現地存続・同じ所有者の別区画との接続・採否・確認日の新しさは任意条件です。接続なしは「同じ所有者の別区画と地続きでない」という確認です。
- 空欄・空白だけの検索語は * と同じ扱いです。

## 5. 順次取得・停止・結果件数

「検索設定 → 取得」のページ数は整数0〜1000、既定0＝無制限です。0は1000ページで打ち切る意味ではなく、正常な終端・停止・失敗まで続けます。1以上は今回取得するページ数の上限です。取得結果は重複を除いて累積します。

検索ページ間の取得間隔は整数0〜60秒、初期値0秒です。これとは別にサーバー側の照会間隔と取得先の待機指定があります。画面を0秒にしても、それらの待機は省略しません。

リンデンのおすすめ行き先ガイド掲載判定は5件ずつ非同期に送り、閲覧・選択・取り込み確認・別候補の編集保存を続けられる構成です。手動操作を優先し、進捗と操作結果を別々に表示します。通信は直列で、同じ照会は有効なキャッシュを再利用します。

「取得を停止」は送信済み処理が返ってから停止し、待機中なら次の送信前に停止します。ブラウザーを閉じると取得は停止します。続きは「追加取得」で再開します。条件一致0件だけを理由に、取得元に続きがある検索を終了しません。

正常な空ページ・最終ページに達した場合だけ「もうこれ以上の候補はありません」と案内します。ページ数上限・手動停止・取得失敗とは別です。「取得情報」で条件、累積件数、取得日時、参照元を確認します。

| 表示 | 意味 |
| --- | --- |
| 一致 | 指定条件に合うと判定した候補 |
| 確認待ち | 未確認の項目があり、一致か不一致か未確定の候補 |
| 不一致 | 指定条件に合わないと判定した候補 |
| 一致と確認待ち | 両方を表示する設定。確認待ちを一致とみなす意味ではない |

「一致0件・確認待ち20件」は20件が不一致という意味ではありません。取得失敗の0件表示と、取得成功した条件不一致の0件表示を区別してください。

## 6. 検索の保存と再開

検索状態のブラウザー自動保存を廃止し、アクセス者が設定したGoogle DriveフォルダーへJSONを自動保存します。ログイン保持・言語設定のブラウザー保存は別です。

「検索設定 → 保存・再開 → 検索JSONの管理」または「設定 → 検索JSONの管理 → 開く」で管理します。保存先の変更はスクリプトの所有者だけが行えます。所有者以外はURLが読み取り専用、変更ボタンがグレー表示です。自動保存・Driveへの手動保存・一覧・読み込み・PCファイル操作は全利用者で維持します。未設定の利用者は所有者の保存先を使い、既存の個人別保存先は保持します。変更をまとめて最初は約5秒後、以後原則30秒以上の間隔で保存し、同じ状態は再保存しません。

- 自動：Auto_SL-Tour-Finder-Linden-search-2026-11-28_15-30-05_UTC.json（UTC日時）。
- 手動Drive保存・PCダウンロードも維持：SL-Tour-Finder-Linden-search-2026-11-29_00-30-05_JST.json（従来のJST日時）。
- 保存後は読み直して一致確認。失敗は自動通知し、同じ要求で再試行できます。保存先未設定を保存済みと扱いません。
- 名前・保存者・JST表示日時・サイズを30件ずつ一覧取得。本文は明示的な読込時に取得します。
- JSONを選び、置き換え確認にチェックして読み込み。共有フォルダーの他スタッフのJSONも同じDB内で引き継げます。読み込みだけでは再検索・DB登録せず、「追加取得」で続けます。以前のブラウザー保存を自動復元しません。
- Drive保存・読込上限4 MiB、PCファイル読込64 MiB。PCファイルは同じ利用者・DBに限定します。

対象は条件・公開取得結果・照会結果・候補の選択・取得位置・表示状態。DB本体・各履歴・写真・名簿・未保存メモ・認証情報は含みません。保存待ち／保存中／確認済み／失敗は管理画面と通知の保存状態で確認します。閉じる前に確認済みを確認してください。未保存時の終了確認はブラウザー制限に従います。

[Googleへの反映・保存先設定](search-json.md)。Main.gs・Index.htmlの更新が必要です。Driveスコープが承認済みなら追加承認不要です。

### 保存済み検索JSONの削除

「検索JSONの管理 → 保存済み」でJSONを選択し、「選択したJSONを削除」を押します。ファイル名・保存者・日時を確認してチェックし、「ゴミ箱へ移動」を実行します。「一覧へ戻る」で中止できます。

移動後の状態を確認し、対象名とともに完了を表示します。既にゴミ箱にある場合は再度変更しません。版・保存先が変わった場合は一覧を更新して選び直します。移動済みと、その後の一覧更新失敗を区別します。復元はファイルの所有者または共有ドライブの管理者へ依頼します。管理者がGoogle Driveのゴミ箱で対象を右クリック→復元します。

現在の検索・候補DB・実施／確認履歴は変更しません。自動保存・手動保存・読込・削除は全ての許可利用者で使えます。所有者限定は保存先変更だけです。

## 7. 候補の取り込みと変更履歴

個別チェック・表示分の選択・取得済み結果全体の選択・解除を使います。全体選択は未取得ページを新たに取得する操作ではありません。一括取り込みは1回500件までです。

| 登録済み候補の処理 | 内容 |
| --- | --- |
| 掲載情報を更新 | 掲載項目を更新し、既存メモ・採否・カテゴリー・確認結果を保持する。空欄・未確認で既知情報を消さない |
| 候補データを置き換え | 取得情報へ置き換え、メモ・採否等を初期状態へ戻す。候補ID・履歴・実施済みの事実は保持する |
| 取り込まない | その候補を変更しない |

新規は新規登録／取り込まないを選びます。掲載写真のURL保存もON/OFFできます。対象名・件数・差分・保存結果を確認してください。名称や所有者等の変更前後を、候補IDとともに既存の確認履歴へ記録します。所有者が変わると、以前の所有者に対する接続確認は未確認へ戻します。

保存と照合は別の結果です。DB保存済みでも掲載・リージョン照会が未処理の場合があります。完了後の「取り込み結果」は閉じた後も再表示でき、見るだけで再保存・再照会はしません。

## 8. 掲載・実施・存続の確認

| 項目 | 判定と操作 |
| --- | --- |
| リンデンのおすすめ行き先ガイド掲載 | 場所検索で出た候補を行き先ガイドで名称検索する。結果があれば掲載あり、正常な0件応答なら掲載なし。検索語・日時・URL・件数を記録する |
| 取得前・失敗したリンデンのおすすめ行き先ガイド掲載判定 | 掲載なしにしない。以前の確認結果を保持し、個別取得／再試行待ちとして扱う |
| SSJツアー | 実施済／未実施を表示する。DBの実施記録0件で過去実施の申告がなければ未実施とし、記録0件という根拠を別表示する。過去に一度も行っていない確認済みという意味ではない |
| リージョン登録 | Linden側のリージョン登録情報。明確な該当なしだけNot in DB。通信・解析失敗は別表示 |
| 現地存続・区画接続 | 現地確認した日付・根拠を記録する。リージョン登録が見つかっただけで施設・パーセルの存続を確認済みにしない |

括弧付きの名称は全文で0件のあと基礎名も検索します。登録済みのガイドURLがあり、検索0件でも掲載ページが存在すれば掲載ありを保持します。URLなし・404だけで掲載なしにはしません。名称検索の結果であり、ガイド全件の網羅証明ではありません。

「この行き先の掲載情報を取得」「この行き先のリージョン情報を取得」は、その行き先の対象項目だけ取得します。未登録候補はDBへ取り込まず確認でき、登録済みは候補ID・版を照合して該当項目を保存します。実際の拒否による待機を解除する操作ではありません。

掲載なしと確認日のない候補は採用へ変更できません。掲載あり等で条件不一致となった選択は取り込み確認時・送信前に再検査し、対象名と理由を示します。実施履歴がある候補は未実施にできず、過去のSSJ記録・スタッフ確認による訂正も履歴へ残します。

## 9. 採否・色・削除・復元

採否は候補／採用／保留／見送りです。「編集・採否」では基本・カテゴリー・取得情報・確認訂正を切り替えます。複数選択から一括編集・情報更新・削除ができます。一括編集は変更項目をチェックし、対象名・件数・内容を確認して保存します。競合時は現在の保存状態を再取得して確認します。

淡い緑は新規、淡い黄色は変更あり、淡い赤は消滅確認済み・削除済み等の復元が必要な候補です。赤の候補は復元まで新しいツアー先に使えません。削除・復元でも候補IDを維持し、実施履歴・確認履歴を失いません。名前変更やシート並べ替えで履歴の対応を変えません。

削除は通常一覧から外す操作です。「削除済み」から戻せます。消滅確認済みは新規登録し直さず、「復元」で現地確認日・根拠を記録します。

## 10. 実施記録・担当者・記念写真

候補の「その他の操作 → 実施を記録」、または「実施履歴 → 実施を記録」を開きます。日付・担当者・ツアー名・メモと、同じ画面で記念写真を保存できます。担当者の初期値はアクセス者本人のメールIDです。表示名は別に関連付け、ツアー名は別の選択肢として登録します。

共有先の個人とグループ内の取得できた個人を担当者候補に表示します。「その他」で任意の担当者も記録できます。名簿取得が一部なら失敗段階を表示し、全員取得済みと扱いません。[名簿の取得と承認](staff-directory.md)を参照してください。

記念写真は1実施記録10枚まで、1枚5 MiB以下、JPEG／PNG／WebPです。実施記録を先に確定し、そのIDへ順番に写真を関連付けます。途中失敗時は、保存済み記録を作り直さず残りの写真だけを再試行します。保存後も「実施履歴 → 記念写真」で追加・確認できます。関連付けを外してもDrive原本・履歴は削除しません。

掲載写真は元URLの参照で、記念写真のDriveアップロードとは別です。[写真の設定と保存手順](photos.md)を参照してください。所有者実行でのアプリ内保存と、スタッフがDrive原本リンクを直接開く権限は別です。

## 12. 照会間隔と再試行の運用設定

所有者がApps Scriptの「プロジェクトの設定 → スクリプト プロパティ」で設定します。

| 名前 | 値 | 未設定時 |
| --- | --- | --- |
| TOUR_LINDEN_REQUEST_INTERVAL_SECONDS | 整数1〜10秒 | 2秒 |
| TOUR_LINDEN_MAX_RETRIES | 整数0〜5回（初回を除く再試行数） | 3回、初回を含め最大4回 |

解析・通信失敗はこの設定で再試行します。0回なら初回だけです。不正値では照会せず設定エラーを表示します。設定は次の実取得から反映し、有効なキャッシュは再利用します。

認証要求・確認用画面・HTTP 401／403／429等は自動再試行しません。HTTP 429は最低60秒、401／403は最低300秒、5xxや再試行後の通信失敗は最低30秒の待機をアプリが設定し、取得先の長いRetry-Afterを優先します。これらはアプリの運用値で、Linden公式が示した固定制限という意味ではありません。解析失敗だけで全照会を5分間止めません。

## 13. 読み込み失敗・保存失敗の確認

UI_INDEX_LOAD／UI_INDEX_FORMATはIndexの読み込み・形式、UI_WORKER_LOAD／UI_WORKER_FORMATはDiscoveryWorkerの読み込み・形式、UI_RENDERはHTMLの組み立て・出力の失敗です。アクセス拒否と区別してください。旧版のUI_VERSION_MISMATCHによる一律停止は現行コードにありません。

画面を開けることと、管理データを取得できることは別です。Google本人確認・グループ照会のエラーは[認証の診断手順](access.md)を使います。保存後の再取得だけが失敗した場合は、保存を重複実行せず「リセット読み込み」で確認します。

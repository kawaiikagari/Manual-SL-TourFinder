# 掲載写真とツアー記念写真

掲載写真はLindenの公開検索で取得した画像URLを候補へ保存して表示します。記念写真は利用者が選んだ画像本体をGoogle Driveへ保存し、実施履歴IDで関連付けます。

## 更新するもの

1. `src/Main.gs`と`src/Index.html`の内容を既存ファイルへ反映します。Apps ScriptのHTML名は`Index`です。
2. 記念写真のアップロードを使う場合だけ、Google上の既存マニフェストの`oauthScopes`配列に次の要素がなければ追加します。配列の既存要素を消さず、要素間のカンマを維持します。

   ```json
   "https://www.googleapis.com/auth/drive"
   ```

3. 所有者がApps ScriptエディターでgetPhotoStorageConfigを実行し、Googleの承認画面が出た場合は必要なDrive権限を確認します。この関数は設定の読み取りだけで、フォルダーへのアクセスや実際のアップロード成功を証明するものではありません。保存先の設定時にはフォルダーへのアクセスも検査します。
4. 既存Webアプリのデプロイを新しいバージョンへ更新します。実行者・アクセス範囲は変更しません。

**ローカルの`appsscript.json`全体をGoogleへ上書きしないでください。** Google本人確認の修正後のソースは、指定済みの所有者実行（`USER_DEPLOYING`）に揃えています。写真保存用の既存Driveスコープは保持します。この写真手順に伴うGoogle側のDrive承認・共有・保存成功は未確認です。Google本人確認のgroups追加承認が済んだことと、写真用Driveの承認は区別します。

このDriveスコープは、Apps Scriptのフォルダーへのファイル保存に必要です。[Google公式のFolder.createFile](https://developers.google.com/apps-script/reference/drive/folder#createfileblob)を参照してください。承認画面ではDriveを管理する権限が求められます。アプリの処理は指定された保存先と、履歴に関連付けた画像を対象とし、Drive全体のファイル一覧取得や共有権限変更はしません。

## 保存先フォルダー

1. Google DriveでSL Tour Finderの記念写真用フォルダーを用意します。
2. 所有者実行のアプリが使う保存先なので、実行する所有者がそのフォルダーへ保存・読み取りできることをDrive側で確認します。アプリ内でのアップロード・縮小画像取得と、スタッフがDrive原本リンクを直接開く権限は別です。原本リンクも使うスタッフには、運用担当者が必要な共有を設定してください。このツールは共有を自動設定しません。
3. Webアプリの「設定 → 写真の保存先」を開き、フォルダーURLを入力して保存します。設定できるのはTourDBの所有者です。

保存先はこのApps Scriptの`TOUR_PHOTO_FOLDER_ID`と`TOUR_PHOTO_FOLDER_NAME`に記録し、変更内容を既存の確認履歴へ追記します。スプレッドシートの列追加・DB初期化は不要です。共有ドライブ、Googleグループ、所有者以外での実動作は未確認です。

保存先として確認した既存フォルダーは、[JapanHiroba → TourDB → TourPhoto](https://drive.google.com/drive/folders/1XWG-d-wCIOY1XSYfweUzYo7vlY5-Pgwj)です。Google上のアプリ設定に反映済みかは未確認です。

## Linden掲載写真

- 公開場所検索の各結果に含まれる`picture-service.secondlife.com`の`159x120.jpg`画像URLを読み取ります。写真を探す追加検索や候補別の巡回はしません。
- カード／一覧で写真を表示します。画像の取得は表示に必要な時にブラウザーが行い、読み込めなければ「写真を表示できません」と表示します。検索やDBの取得失敗とは区別します。
- 一括取り込みの確認画面で「取得した掲載写真のURLを保存する」をON/OFFできます。写真が取得できなかった候補について、既存の写真を消しません。
- 個別編集でも掲載写真のURLを確認・解除できます。変更前後・掲載元・取得日時・利用者は既存の確認履歴へ保存し、候補IDで関連付けます。
- 画像本体はコピーせず、元のURLを参照します。元画像が利用できなくなると表示できません。写真があることを、現地存続や約1時間のツアー適性の確認とは扱いません。

## 記念写真を保存する

1. 候補の「実施を記録」を開きます。実施日、プルダウンの担当者・ツアー名、メモを入力します。担当はアクセス中のGoogleメールIDが初期値です。
2. **同じ画面**の「記念写真を選択」で数枚まとめて選び、必要なら写真ごとの説明を入力します。1つの実施記録につき10枚まで・1枚5MiB（5 × 1024 × 1024バイト）以下のJPEG／PNG／WebPです。
3. 「実施記録と写真を保存」を押します。実施記録を先に確定し、その実施履歴IDへ写真を1枚ずつ保存します。進行状況と写真名を表示します。
4. 写真で途中失敗した場合も、実施記録と保存済み写真は保持します。実施日・担当・ツアー名は保存済みとして固定し、「未保存の写真を保存」で残りを再試行できます。同じ実施記録を作り直しません。
5. 保存後も「実施履歴 → 記念写真」で確認・追加できます。同じ候補の別の回は別アルバムです。Drive保存後の履歴記録だけ失敗した場合は、同じ記録ID・ファイル名で既存ファイルを再利用します。

画像のバイト列はDBに保存しません。DriveファイルID・原本リンク・実施履歴ID・説明・日時・利用者を既存の確認履歴に追記します。候補名の変更、行の並べ替え、候補の削除・復元でも関連付けを維持します。ブラウザー内の選択ファイルはダイアログを閉じても、そのページを開いている間保持します。ブラウザー自体を再読み込みすると、保存前のファイル選択は失われます。

アルバムを開いた時だけ、認証済みのサーバー処理でDriveの縮小画像を取得します。同じ画像への処理中の取得は共有し、取得成功は5分、表示不可は30秒再利用します。「写真を再読み込み」で明示的に再取得できます。Driveがまだ縮小画像を用意していない場合や、実行者に読み取り権限がない場合は表示不可となり、原本リンクから確認できます。[Google公式のFile.getThumbnail](https://developers.google.com/apps-script/reference/drive/file#getthumbnail)も参照してください。

「この実施履歴から外す」は関連付けだけを解除します。Driveの原本と変更履歴は削除しません。

## 確認した範囲

ローカルの代替Drive・DB・DOMで、写真付き候補の表示、一括取り込み、複数アップロード、入力検証、競合、途中失敗と再試行、関連付け保持を検証しています。Google Driveへの実保存、実ブラウザー表示、OAuth承認、グループ共有、Driveの縮小画像生成は未確認です。ローカルプレビューはDrive保存・設定を明示的に利用不可とし、架空の保存成功を返しません。

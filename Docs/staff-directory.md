# 共有先から担当者を選ぶ

実施記録と担当者登録のメールID欄は、TourDBの共有先に登録された個人と、共有先Googleグループから取得できた個人メンバーをプルダウン表示します。グループアドレス自体は個人の候補に入れません。重複・削除済み・期限切れ・参加禁止・招待中・承認待ちは除き、子グループも取得上限内で展開します。「その他」では任意のメールIDを入力できます。

実施記録の初期選択はアクセス中の個人メールIDです。表示名は別に保持し、登録済みの担当者表示名を優先します。共有一覧にGoogleの表示名があれば初期表示に使います。グループからメールIDだけ取得できた人の表示名は推測しません。この一覧は記録の入力補助で、アプリの利用権限を付与する処理ではありません。

通常利用で共有先アドレスやグループのメンバーを手入力登録する必要はありません。記録画面を開いた時に取得し、同じ実行利用者のキャッシュを再利用します。「共有先メンバーを再取得」で更新できます。選択済みの人・入力・写真は再取得で失いません。

## Google側の初回承認

共有先名簿の取得では、`src/appsscript.json`に登録済みの次の2スコープを使います。Google本人確認の追加に伴う新しいスコープはありません。Google側の既存マニフェストは、**ファイル全体で上書きせず、`oauthScopes`配列に存在しない要素だけ追加**します。実行者・公開範囲・共有先、写真保存用など既存のスコープは維持してください。

```json
"https://www.googleapis.com/auth/drive.metadata.readonly",
"https://www.googleapis.com/auth/groups"
```

既存マニフェストは、対象TourDBのApps Scriptエディターで「プロジェクトの設定 → appsscript.json マニフェスト ファイルをエディタで表示する」を有効にした時、ファイル一覧に出る既存の`appsscript.json`です。他のプロジェクトは使いません。コードとスコープを保存した後、所有者が既存エディターの関数選択でcheckTourGoogleLoginGroupを実行し、不足するGoogle承認を確認します。マニフェストの記載と承認済みは別です。承認後にもう一度実行し、アプリの「共有先メンバーを再取得」で担当者一覧を確認します。グループ照会と名簿取得は読み取り用で、共有先・権限・DBデータを変更しません。

Driveの共有情報はTourDBの固定IDだけに対して`permissions.list`で取得します。REST APIを利用できない構成では取得結果に「Google Drive APIを利用できません」と表示します。その場合だけ、対象Apps Scriptに接続されたGoogle CloudプロジェクトのDrive API利用状態を確認します。この開発作業でGoogle Cloud設定やデプロイを変更してはいません。

## 一覧が一部になる場合

Googleグループのメンバー一覧とメールアドレスを閲覧できる必要があります。Apps ScriptのGroupsサービスが返す、対応するGoogleアカウントのある個人が自動取得の対象です。閲覧できないグループ、非公開のメールID、取得上限、通信失敗などは「一部取得」として表示し、全員取得済み・メンバー0人とは説明しません。取得できた個人、既存の担当者登録、アクセス者本人、「その他」は引き続き選択できます。失敗した段階（グループの照合／メンバー・メールIDの取得／在籍状態の確認／子グループの取得）を最初から展開して表示します。一般的な取得失敗を「閲覧できません」とは断定しません。Googleが返した例外文は、認証情報とURLを除去した短い文字列として表示します。承認・取得制限のエラーでは同じ在籍確認を続けません。1人の不整合でまとめて役割を取得できない時は上限付きで分割し、他の確認済みメンバーを保持します。

キャッシュは利用者単位で、全利用者共通のキャッシュにメンバー一覧を保存しません。成功時は5分、一部取得時は1分再利用します。1回の処理は共有情報10ページ・グループ30件・個人500人・子グループ深さ5・処理時間の目安15秒・在籍状態照会120回に制限し、上限に達した場合も一部取得と表示します。DBにメンバー一覧の列やシートを自動追加しません。

## 現在の実行方式と確認範囲

現行ソースのWebアプリ設定はUSER_DEPLOYING／ANYONEです。スタッフの利用許可は指定グループへの所属で判定し、名簿の取得・任意登録から利用権限を与えません。キャッシュのキーには確認済みの利用者と対象DBを含め、所有者実行でもスタッフごとの一覧を取り違えない構成です。

2026-11-27までの実画面でGroupsAppの不足承認が判明し、所有者から追加承認とGoogle本人確認完了の報告があります。名簿の全員取得成功や、全スタッフの実操作成功まで確認したことにはしません。過去のUSER_ACCESSING前提の案内ではなく、[現行の本人確認とグループ利用許可](access.md)を使ってください。

Google公式資料：[ファイル共有先の取得と必要スコープ](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions/list)、[グループのメンバー・子グループと閲覧条件](https://developers.google.com/apps-script/reference/groups/group)、[メンバーのロール](https://developers.google.com/apps-script/reference/groups/role)。
